# FAQ Builder

## Read first
- Real questions: support messages the owner shares, triage notes, call notes.
- `projects/<project-slug>/strategy/intake.md`, the positioning and pricing memos.
- An existing FAQ or help canvas: improve it, never start a second one.
- No real questions yet: ask for the five most common, or draft from the onboarding
  steps and mark the list as a guess to check.

## Method
1. **Collect and count** the questions; merge ones that mean the same.
2. **Rank** by how often they come up and how much they block (a setup question
   before value beats a curiosity).
3. **Write each answer:**
   - The question as customers ask it.
   - The answer in the first sentence.
   - Steps, numbered, if there are steps.
   - One line on what to do if it did not work (contact, link).
4. **Group** by stage: before buying, getting started, everyday use, billing, leaving.
5. **Find fixes at the source:** a question asked often may mean the product or the
   page should change. Note it for @product as a suggestion.

## Options
Where to put it: a help canvas pinned in a channel, a page on the website (draft text
for the owner), or answers inside onboarding messages. Trade-off: reach against upkeep.

## Recommendation
The top questions to answer first, where to put them, and the one product or page
change that would remove the most questions.

## Before you reply
- Each answer starts with the answer, not with background.
- Nothing is promised that the product does not do.
- No customer names or details in public answers.

## Write gate
Show the FAQ in chat. Save it as a canvas page (`create-canvas`, then `add-block --type text`) only after the user approves.
