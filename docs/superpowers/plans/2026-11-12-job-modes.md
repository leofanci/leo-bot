# Job Modes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jobs get a mode (Approval, Auto, Report only), and only an owner click creates, changes or deletes a job.

**Architecture:** The mode lives on the job record. A job turn carries its id and mode into every osctl path (TurnPolicy, os_relay context, `LEOBOT_JOB*` env), and osctl, the apps relay and the server enforce the mode table. Bots stop writing jobs: `osctl propose-job` drops a proposal into an outbox in `team/jobs.json`, keyed by the thread; at turn end the server re-validates it and turns it into a `job` approval card. Approve applies it. The Team screen lists jobs with mode, on/off and delete.

**Tech Stack:** Python stdlib server, vanilla JS dashboard, unittest.

**Spec:** `docs/superpowers/specs/2026-11-12-job-modes-design.md`

## Global Constraints

- Modes: `approval` (default), `auto`, `report`. A job with no or unknown `mode` reads as `approval`.
- Auto: osctl creates and updates run; every `delete-*` command, `remember` and `propose-job` are refused.
- Approval and Report only: `LEOBOT_READONLY` stays on. Report only drops APPROVAL lines and refuses app writes at the relay instead of holding them.
- No bot path creates, changes or deletes a job: `create-job`, `update-job`, `delete-job` leave osctl.
- `propose-job` is refused in shared threads, read-only turns and job turns of any mode, and outside a chat turn (no `LEOBOT_CHAT`).
- Job cards: never resolved by a new message, never superseded, expire after `approvals.APP_TTL`, Approve owner-only and exactly once.
- Public repo: fixtures use `demo`, `acme`, `profile-a`, `profile-b` only; run `tests/test_no_usage_data.py` before each commit.
- No `Co-Authored-By` trailer in commits.

## Review Focus

- A proposal written from one workspace's thread naming another workspace's job or bot: refused at osctl and again at collection (test in Task 2).
- A job deleted or edited between proposal and Approve: Approve fails with a clear line, nothing half-applied (Task 2).
- Double Approve (two tabs): second click gets 409, job created once (Task 5).
- A proposal left by a turn that never collects it (spoofed chat id, crash): pruned after a day, never shown in another thread (Task 1).
- A generate run in an Auto job past the job's cap: refused before the model runs (Task 6).

### Task 2: Job cards: validation, approvals kind, apply

**Files:**
- Create: `dashboard/job_cards.py`
- Modify: `core/approvals.py`
- Test: `tests/test_job_cards.py`, `tests/test_approvals.py`

**Interfaces:**
- Consumes: Task 1.
- Produces:
  - `job_cards.check_target(root, ws, bot, skill, projects) -> None` (ValueError: workspace gone, bot inactive, skill not owned, engine refused or unmetered; moved from osctl `_job_target`).
  - `job_cards.proposal(root, *, thread_ws, op, job_id=None, fields: dict, projects) -> dict` returning `{"op", "job_id", "fields", "summary", "preview": {"title", "fields": [[label, text], ...]}}`. `op` in `create|update|delete`. Create needs bot, skill, name, message, schedule, cap; `mode` defaults `approval`; target workspace = `fields["workspace"]` or thread_ws, and a non-HQ thread may only target itself; job count below `MAX_JOBS`. Update: job exists and in scope, fields ⊆ name, message, schedule, cap, skill, mode, at least one, a new skill re-checks target. Delete: job exists and in scope. Summary `New job: <name>` / `Change job: <name>` / `Delete job: <name>`. Preview rows for create: Bot (`@bot /skill`), Workspace, Schedule, Next run (local `%a %d %b %H:%M`), Mode (`Approval: saves wait for your click` / `Auto: saves by itself, deletes, memory and app actions wait for you` / `Report only: reads and reports, saves nothing`), Cap (`$N per 24 hours`), Message. Update rows: `<field>`: `old → new`.
  - `job_cards.apply(root, rec, projects) -> str` re-runs `proposal` from the stored row, then `jobs.create/update/delete`; returns the result line (`Job created: <name>, next run <when>.` / `Job changed: <name>.` / `Job deleted: <name>.`), ValueError on any refusal.
  - `approvals.JOB = "job"`; `approvals.add_job(root, *, ws, room, chat, bot, job: dict, summary, preview) -> dict`; held kinds `{APP, JOB}` share protection (not resolved, not superseded, kept by `_save`, expired after `APP_TTL`); `claim`, `finish`, `reject` accept both kinds; `approvals.edit_job_fields(aid, fields, root, preview, job)` (pending only).

- [ ] Tests (`tests/test_job_cards.py`, temp root with `acme` workspace fixture as `tests/test_jobs.py` builds it): create proposal ok and preview rows; non-HQ thread targeting `demo` refused; unknown bot refused; update of missing job refused; update with no fields refused; delete in scope ok; `apply` creates once, then `apply` of an update after the job was deleted raises; `apply` re-checks the target (bot switched off between proposal and Approve → ValueError, no job).
- [ ] Tests (`tests/test_approvals.py`): job row survives `resolve_chat` and a newer `add`; `claim` twice → second ValueError; week-old pending job row expires in `pending()`.
- [ ] Run both, expect FAIL. Implement. Run, expect PASS. Commit.
