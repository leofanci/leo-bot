# Engines Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Each step below is one PR, tests green, merged before the next.

**Goal:** bots run on Claude Code, an API key, Codex or any ACP CLI; Leo Bot runs always-on on a server; invited people never use the owner's login.

**Architecture:** `dashboard/engines/` holds one driver per engine behind `Engine.turn()`, which yields the event tuples the server already consumes. `ChatSession` keeps thread state and delegates process or HTTP work to its engine. The server picks the engine per run.

**Tech Stack:** Python stdlib only (urllib, subprocess, http.server), vanilla JS.

**Spec:** `docs/superpowers/specs/2026-11-04-engines-design.md`

## Global Constraints

- No third-party Python dependencies.
- `tests/test_no_usage_data.py` before every commit; fixtures use `demo`, `acme`, `profile-a`, `profile-b`.
- A shared turn offers only osctl (plus web per policy) on every `shared_safe` engine.
- Keys live in `team/engines.json` (0600), never in an API response, argv or a bot-readable file.

## Review Focus

- A thread that moves between engines: the new engine gets a recap of visible messages, never another engine's transcript.
- A saved chat whose Claude session is gone (moved to a server): the next turn recovers with a recap instead of failing.
- An invited person's `generate-*` job: runs on the API key engine, not the owner's login.
- `web_fetch` on a host that resolves to a private address (cloud metadata on a VPS): refused.
- Server restart: the owner's login link and cookie keep working.

## Steps

1. **Engine interface + claude-code driver.** Create `dashboard/engines/{__init__,base,claude_code}.py`. `ChatSession` public API and every existing test stay unchanged.
2. **API driver and routing.** Create `dashboard/engines/{config,api,api_tools}.py`. Provider config in `team/engines.json`. Anthropic and OpenAI-compatible streaming, tool loop, history file per chat and provider. Engine picked per run in `server._ask_turn`; invited people go to the `people` engine or get a clear message. Recap via `chat_store`. Engines screen in HQ. `generate.py` and the terminal go through the engine layer in the same step, because an invited person's job must not fall back to the owner's login.
3. **Server packaging.** `MYOS_DEPLOYMENT=server` (stable owner token, Mac-only features off), `scripts/server-setup.sh`, `scripts/myos-connect.sh`, `scripts/sync-to-server.sh`, `docs/server.md`.
4. **Runners.** `core/runners.py`, `dashboard/engines/runner.py`, `dashboard/runner.py`, `/api/runner/*`.
5. **Codex driver**, with the live probe recorded in the PR.
6. **ACP driver**, live-tested against an installed ACP CLI.
